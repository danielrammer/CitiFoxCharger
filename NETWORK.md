# Home network access

One Windows tablet runs the backend and monitor. Other devices open the same dashboard and can operate the charge target, start/stop and permitted outputs. Closing any browser does not stop the tablet monitor or create extra Škoda polling loops.

Home network access starts **disabled**. Local administration remains **http://127.0.0.1:8765/**. The optional listener uses **HTTPS**, normally port **8766**, bound to a specific private tablet IPv4 address. There is no wildcard bind or unencrypted network listener.

## 1. Configure on the tablet

Run **Setup-Network.cmd** under the Windows user that runs CitiFoxCharger. Python 3.11+ and Windows/.NET Framework 4.7.2+ are required. Save the MyŠkoda key with Windows encryption before a backend restart. Encrypted keys from another PC cannot simply be copied.

Confirm the suggested tablet IPv4 address. The suggestion uses the route to Smartfox without sending a UDP packet. It must be the address of this tablet, for example **192.168.0.95** if that is its current assigned address.

Choose one access mode at the password prompt:

- **Password protected:** enter a separate password of 12–128 characters and repeat it. Other devices sign in as **citifox**. The password is stored only as a salted PBKDF2-HMAC-SHA256 hash.
- **Without a password:** leave the prompt empty and press Enter. This explicitly allows **all devices on the reachable home network to view the dashboard and operate charging and heaters, view/download sanitized diagnostics and trigger confirmed application updates**. No login is required. HTTPS, session/CSRF checks, local-only credential/device administration and network restrictions stay in place.

Existing configurations without an explicit mode remain password protected. An invalid configuration does not silently become passwordless. To change the mode, run Setup-Network.cmd again; certificate regeneration requires importing the new public certificate on client devices.

Setup generates individual certificates, restarts the backend cleanly and checks that the listener actually started. Existing monitoring resumes without a new vehicle start. If the listener fails, local monitoring continues and Settings shows the error. The script displays the exact URL and SHA-256 certificate fingerprint, and stays open until a key is pressed.

Reserve the tablet IP in the router if possible. An IP change or certificate expiry after two years requires setup and client certificate trust again. No router port forwarding is needed for home network access.

## 2. Allow the private subnet in Windows Firewall

Right-click **Setup-Firewall.cmd → Run as administrator** on the tablet. This is a separate deliberate setup step. Windows must classify this home network as **Private**.

The rule **CitiFoxCharger-Private-LAN** permits only the configured Python executable, tablet IP, HTTPS port, **LocalSubnet** and **Private** profile. It does not disable Windows Firewall or allow the Public profile. Re-run firewall setup if a Python upgrade changes the executable path. [Microsoft firewall rule documentation](https://learn.microsoft.com/en-us/powershell/module/netsecurity/new-netfirewallrule).

## 3. Trust the public certificate on each client

Setup exports **CitiFoxCharger-Home-Network.cer** into the program folder when writable. The original is always in the active profile under **network**. The profile is normally `%LOCALAPPDATA%\CitiFoxCharger`; existing installations retain `%LOCALAPPDATA%\Ladezentrale`.

Since 1.10.3, **Settings → Home network access → Download public certificate** downloads this same public CER file through `GET /api/network/certificate`. The link appears only when the active profile contains the certificate. It works locally and over the configured home-network listener using the existing authentication/session/origin checks. Only a complete, validated DER X.509 certificate is served; keys, appended data, arbitrary paths and oversized files are rejected. It does not install certificate trust, generate a certificate or change the running listener. A device that cannot yet open HTTPS may still need the public file transferred from the tablet or another trusted device for its first trust setup.

Copy only this public CER file to the other device and compare its SHA-256 fingerprint with the tablet display. Private key/data folders are not needed. Trust only the certificate generated by your own tablet.

- **Windows:** run `certmgr.msc` for the current user. Under **Trusted Root Certification Authorities → Certificates**, choose **All Tasks → Import** and import the public CER file. This is an explicit trust decision. [Microsoft certificate store documentation](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/trusted-root-certification-authorities-certificate-store).
- **Android:** search Settings for **Install certificate** and install the file as a **CA certificate**. On Pixel, see Security and privacy → More security settings → Encryption and credentials; manufacturers may name this differently. [Google certificate instructions](https://support.google.com/pixelphone/answer/2844832?hl=en).

The application does not install trust automatically or bypass browser certificate warnings. If a certificate error remains, check IP, clock, fingerprint and import. Firefox may use its own certificate store. Passwordless access still requires a valid trusted HTTPS connection.

## 4. Open the dashboard

Use the exact HTTPS URL shown by setup, for example **https://192.168.0.95:8766/** only if that is the configured tablet address. Password mode prompts for **citifox** and your network password. Passwordless mode opens directly after certificate trust.

All network clients share the same monitor and target. Language, theme and an inactive preferred target are browser preferences; an active target is shared backend state. API keys, device configuration, generic vehicle commands and backend exit/restart remain local-only in both access modes. The vehicle key never goes to another browser.

## Disable or troubleshoot

Since 1.10.2, opening the static landing page through an external link is allowed when the browser identifies a top-level GET navigation. Previously this could produce `Access from another website is not allowed`, particularly when opening a link on a phone. API reads, session bootstrap, embedded documents and all commands retain the existing origin/session/CSRF and authentication checks. This error is an application policy rejection, distinct from a TLS certificate warning or connection reset.

Run `Setup-Network.cmd --disable` to disable the listener after a clean restart. Remove only the application firewall rule as administrator if no longer required:

```powershell
Remove-NetFirewallRule -Name CitiFoxCharger-Private-LAN
```

On timeout check that the tablet/backend are running, the URL/IP is correct, both devices share a reachable home network, guest-Wi-Fi isolation is absent, Windows uses the Private profile and the firewall rule is installed. Local Settings → Home network access reports listener errors. Password mode throttles five failed sign-ins per client for up to a minute. Passwordless mode intentionally has no password challenge.

Custom profile/ports:

```powershell
Setup-Network.cmd --data-dir "C:\MyDataFolder" --backend-port 8765 --port 8766
Setup-Firewall.cmd --data-dir "C:\MyDataFolder"
```

Use the same profile already used by the backend. Setup windows remain open after success and failure. Certificate creation, strict TLS, both authentication modes and permission boundaries are tested on loopback. A successful physical second-device connection to this wall tablet still requires confirmation.

For the communication diagram and exact device/cloud interfaces, see [COMMUNICATION.md](COMMUNICATION.md). Use **HTTPS**, not plain HTTP, on the network listener port 8766; HTTP sent to that TLS port can be reset before any application response.

## Planned public reverse-proxy access

Public access is not enabled by the current home-network setup. A separate gateway can provide a real domain, publicly trusted HTTPS and mandatory authentication while retaining passwordless private-LAN access. Such a gateway must verify the tablet's upstream TLS certificate and preserve the application's Host/origin/session/CSRF checks; a generic reverse proxy is not automatically compatible with the current IP-only allowlist. Do not disable these checks or forward the tablet's ports directly to the Internet. Public routes should exclude device/key administration, backend process control, updates and experimental vehicle-limit commands. Review the existing gateway before changing ports or services.


## Remote diagnostics and updates

From Settings, authenticated home-network sessions can view/download `GET /api/diagnostics`, start `POST /api/app/update` and follow `GET /api/app/update/status`. This is also enabled in explicitly configured passwordless mode: every reachable home-network device can trigger an update. Update confirmation appears before submitting; existing charging guards, encrypted-key requirement, expected-repository/fast-forward checks, private-host/origin/session/CSRF checks and backend restart verification remain. Standalone backend restart/exit and key/device configuration stay local-only. Diagnostics use cached allowlisted data and never trigger a vehicle request or charging command. The first upgrade to 1.8.11 must still be launched on the tablet because earlier backends reject remote updates.

Since 1.10.4, the download stays on the Settings page, uses the existing browser session and reports failed requests below the button. A successful response is handed to browser downloads as a CER file; this is not a certificate-trust installation or proof that the browser saved the file. If the download fails, report the displayed message and the exact app address. Certificate downloads remain available through local/LAN access. The restricted public gateway below excludes this certificate-download endpoint and hides its button.

## Public gateway (explicit opt-in)

The gateway and the tablet have separate responsibilities. Apache on omdev terminates
public HTTPS and requires the local `dnl` Basic password on **every** public
resource, including static assets, session bootstrap, diagnostics and API routes.
The existing tablet HTTPS listener continues to use its current LAN access policy.
Only the tablet owns the Service, monitor, adapters, vehicle quota and charging state.
Never launch `run.py` or a production backend on omdev.

The tablet additionally reads `public-gateway.json` from its **active data profile**:

```json
{
  "origin": "https://citifox.ancora.cyou",
  "proxy_ip": "192.168.0.98",
  "token_sha256": "<SHA-256 of a randomly generated 32-byte hexadecimal assertion>"
}
```

Generate the assertion locally with a cryptographic random generator. Store its raw
value only in the root-protected Apache include `/etc/httpd/citifox/gateway-header.conf`.
The tablet receives only its SHA-256 digest. Neither value belongs in Git, chat,
command arguments or request logs. The configuration is optional; malformed or absent
configuration leaves public requests denied while preserving existing LAN access.
Restart the tablet using its guarded update/lifecycle process after installing code
and this profile file. Do not force a restart while the existing lifecycle guard blocks it.

For each public request the tablet requires **all three**: the actual TCP peer must
be the configured private proxy IP, Host must match the exact configured public
hostname, and `X-CitiFox-Gateway` must match the assertion digest. Apache replaces any
client-supplied assertion after checking the password. This narrowly scoped assertion
attests to the gateway's login decision; it never grants local administration.
`Forwarded` and `X-Forwarded-*` do not grant permissions or change client identity.
Reserve omdev's IP; do not expose the tablet ports through router forwarding.

The original public authority and Origin are preserved for the tablet checks. With
Apache, `ProxyPreserveHost Off` makes TLS verify the tablet certificate CN instead
of incorrectly expecting the public domain on the tablet certificate. The proxy
sets `X-CitiFox-Public-Host` to the **fixed configured public hostname**, after
rejecting any other incoming Host, and replaces any client-supplied header. The
tablet accepts it only with the verified gateway assertion, exact TCP peer and
exact transport Host `citifoxcharger:<actual listener port>`. Other forwarded
headers remain irrelevant. The tablet still checks exact public HTTPS Origin,
fetch metadata, browser session and CSRF. Public cookies
use `lz_public_session` with Secure, HttpOnly and SameSite=Strict; public CSRF and
session tokens are separate from LAN/local tokens. Public access allows status,
sanitized diagnostics, refresh, normal charging start/stop/target and existing heater
and charger modes. Updates (including update status), backend quit/restart, device/key
configuration, arbitrary commands and all experimental limit-test/guard overrides
are denied. The UI hides unavailable controls. LAN permissions are unchanged.

### Apache deployment on omdev

Reuse the existing Apache and Certbot installation; do not add a competing listener
on ports 80/443. Back up the main config and every changed vhost with root-only
permissions. Include CitiFox **after** the existing Maya vhost so the existing default
host and Maya certificate are preserved. The checked-in templates under `deploy/`
contain no credentials. `citifox-closed.conf` serves only ACME HTTP challenges and a
fixed redirect. `citifox-tls-closed.conf` provides a password-protected holding page
without any upstream connection. Unknown public application routes remain denied by
both the gateway allowlist and tablet policy after activation.

1. Check authoritative and recursive A/AAAA DNS. A must resolve to the router's WAN
   address; remove or correctly route a stale AAAA. Verify the router forwards only
   80/443 to omdev, never 8765/8766 to the tablet. A LAN request to the WAN address
   proves only NAT loopback, not external reachability.
2. Install the HTTP-only vhost and challenge directory. Run `httpd -t` before a
   graceful reload. Obtain the certificate using Certbot webroot; this preserves Maya.
3. Set the gateway password locally in a visible terminal. Store only a bcrypt
   password hash in `/etc/httpd/citifox/users.htpasswd` (root:http, mode 0640).
   Do not put a password in an argument, environment variable, chat or log.
4. Install the HTTPS holding vhost. Verify missing/wrong login yields 401 for `/`,
   `/app.js`, `/api/session`, `/api/status` and `/api/diagnostics`. Verify the correct
   password locally, without printing credentials or session tokens.
5. Copy **only** `CitiFoxCharger-Home-Network.cer` from the tablet. Compare its SHA-256
   fingerprint with the tablet's own displayed fingerprint over an independent
   trusted channel. Convert DER to PEM if needed. Verify the upstream chain, expiry
   and IP SAN for `192.168.0.95` with this CA. Apache 2.4 name checking uses DNS SANs
   and CNs, so the template uses the existing certificate CN `CitiFoxCharger` as
   its upstream name. Back up `/etc/hosts`, check for conflicts, and add the fixed
   alias `192.168.0.95 citifoxcharger`. Use `ProxyPreserveHost Off` plus the
   fixed authenticated public-authority header, as explained above. Confirm the live leaf
   has that CN as well as the correct IP SAN before activation. Never use `-k`, `verify=False`,
   `SSLProxyVerify none`, or disable peer-name checks. Never copy tablet private keys.
6. Install the application changes and the profile gateway digest on the tablet via
   its normal guarded update process. Prove the assertion works with Host/Origin
   intact and that direct LAN remains passwordless. Use **simulated adapters only**
   for switching tests; production validation is read-only.
7. Insert `citifox-proxy.inc.example` into the password-protected TLS vhost only after
   the above checks. Its secret include is generated locally, outside Git. Keep
   Basic authentication covering the entire vhost. Check Origin/session/CSRF rejection,
   route denial and correct-password normal read access again before declaring ready.
8. Ensure `httpd.service` and the existing `maya-cert-renew.timer` remain enabled.
   That timer invokes `certbot renew` for **all** certificate lineages. The existing
   deploy hook validates Apache and gracefully reloads it. Run a lineage-specific
   Certbot renewal dry run. Do not start another conflicting renewal job.
9. Finish with a real mobile-data test (Wi-Fi disabled), including valid browser
   certificate trust, missing/wrong/correct login and ordinary reads. Record whether
   this was actually completed; do not infer it from LAN or NAT-loopback results.

Access logs must omit Authorization, Cookie, CSRF, gateway assertions, query strings
and bodies. The templates log only address, time, HTTP method, status and byte count.
The ACME HTTP challenge is a public static token, not an application/API bypass.

### Disable only public access

Restore `/etc/httpd/conf/extra/citifox-tls-closed.conf` to the authenticated holding
vhost (remove the ProxyPass and gateway include), validate with `httpd -t`, then
`systemctl reload httpd`. Keep the CitiFox HTTP challenge vhost for renewal and keep
Maya's vhost untouched. This disconnects public access without contacting or restarting
the tablet; its LAN dashboard and monitoring continue. Deleting the tablet's
`public-gateway.json` during a later safe restart also removes gateway trust, but is
not required for immediate shutdown of public access. Do not stop Apache because
that would also interrupt Maya.


### Assisted final activation on omdev

The existing protected transfer file is outside Git at
`/home/dnl/Work/CitiFoxCharger/gateway-transfer/public-gateway.json`.
Copy it to the **active tablet data profile**, directly beside `network.json`.
Do not place it in the program folder or the `network` certificate subdirectory.
Existing installations normally use `%LOCALAPPDATA%\Ladezentrale`; newer profiles
use `%LOCALAPPDATA%\CitiFoxCharger`. Respect any explicitly configured data directory.
Use a secure file transfer or a trusted removable drive. Do not paste the assertion
digest into chat. A Windows client can alternatively retrieve the file over SCP
from `dnl@192.168.0.98`; verify the server's SSH host fingerprint independently.

The tablet loads this configuration on startup. Use the existing guarded
`Restart.cmd` from the installed program folder; do not bypass a refusal or force
process termination. This loads the gateway policy without issuing a charging
start. It must continue to use the same profile and single monitor.

After the current public tablet CA has been staged as
`gateway-transfer/tablet-current-ca.pem`, run locally on omdev:

```bash
sudo python /home/dnl/Work/CitiFoxCharger/source/deploy/activate_omdev.py
```

The script reads the existing gateway assertion only in memory, validates its
match with the transferred configuration, checks the live tablet TLS and unchanged
passwordless LAN policy, and verifies public role/origin/session/CSRF boundaries.
It never issues normal charging, target, heater or refresh commands. Negative POST
checks use payloads that cannot perform process/configuration operations.
If the tablet has not loaded its gateway profile, it stops before changing proxy
configuration. Otherwise it asks for the existing **public** password locally.

It saves root-only backups of the affected Apache config, hosts file and proxy CA,
adds the fixed tablet alias and verifies the candidate Apache proxy in a separate
process with a listener bound only to loopback. This does not reload the shared
production Apache service. After final activation, the script explicitly waits for
the asynchronous production reload to serve the new gateway configuration. Missing/wrong login and strict upstream TLS are checked
before replacing the public holding site. Errors restore the original holding configuration and reload Apache, or start
it if it has stopped. A newly staged public CA remains available so an in-flight
reload cannot lose its certificate dependency. After activation it rechecks the public role boundaries,
tablet LAN and Maya. This is local validation; confirm external HTTPS separately
using mobile data with Wi-Fi disabled.

To disconnect only public application access, without contacting the tablet:

```bash
sudo python /home/dnl/Work/CitiFoxCharger/source/deploy/activate_omdev.py --disable
```

This restores the authenticated holding vhost while preserving Maya, ACME renewal
and tablet monitoring. Do not stop the shared Apache service.
