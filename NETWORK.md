# Home network access

One Windows tablet runs the backend and monitor. Other devices open the same dashboard and can operate the charge target, start/stop and permitted outputs. Closing any browser does not stop the tablet monitor or create extra Škoda polling loops.

Home network access starts **disabled**. Local administration remains **http://127.0.0.1:8765/**. The optional listener uses **HTTPS**, normally port **8766**, bound to a specific private tablet IPv4 address. There is no wildcard bind or unencrypted network listener.

## 1. Configure on the tablet

Run **Setup-Network.cmd** under the Windows user that runs CitiFoxCharger. Python 3.11+ and Windows/.NET Framework 4.7.2+ are required. Save the MyŠkoda key with Windows encryption before a backend restart. Encrypted keys from another PC cannot simply be copied.

Confirm the suggested tablet IPv4 address. The suggestion uses the route to Smartfox without sending a UDP packet. It must be the address of this tablet, for example **192.168.0.95** if that is its current assigned address.

Choose one access mode at the password prompt:

- **Password protected:** enter a separate password of 12–128 characters and repeat it. Other devices sign in as **citifox**. The password is stored only as a salted PBKDF2-HMAC-SHA256 hash.
- **Without a password:** leave the prompt empty and press Enter. This explicitly allows **all devices on the reachable home network to view the dashboard and operate charging and heaters, view/download sanitized diagnostics and trigger confirmed application updates**. No login is required. HTTPS, session/CSRF checks, local-only credential/device administration and network restrictions stay in place.

Existing configurations without an explicit mode remain password protected. An invalid configuration does not silently become passwordless. To change the mode, run Setup-Network.cmd again; certificate regeneration requires importing the new public certificate on client devices.

Setup generates individual certificates, restarts the backend cleanly and checks that the listener actually started. Existing monitoring resumes without a new vehicle start. If the listener fails, local monitoring continues and Settings shows the error. The script displays the exact URL and SHA-256 certificate fingerprint, and stays open until a key is pressed.

Reserve the tablet IP in the router if possible. An IP change or certificate expiry after two years requires setup and client certificate trust again. No router port forwarding is needed for home network access.

## 2. Allow the private subnet in Windows Firewall

Right-click **Setup-Firewall.cmd → Run as administrator** on the tablet. This is a separate deliberate setup step. Windows must classify this home network as **Private**.

The rule **CitiFoxCharger-Private-LAN** permits only the configured Python executable, tablet IP, HTTPS port, **LocalSubnet** and **Private** profile. It does not disable Windows Firewall or allow the Public profile. Re-run firewall setup if a Python upgrade changes the executable path. [Microsoft firewall rule documentation](https://learn.microsoft.com/en-us/powershell/module/netsecurity/new-netfirewallrule).

## 3. Trust the public certificate on each client

Setup exports **CitiFoxCharger-Home-Network.cer** into the program folder when writable. The original is always in the active profile under **network**. The profile is normally `%LOCALAPPDATA%\CitiFoxCharger`; existing installations retain `%LOCALAPPDATA%\Ladezentrale`.

Copy only this public CER file to the other device and compare its SHA-256 fingerprint with the tablet display. Private key/data folders are not needed. Trust only the certificate generated by your own tablet.

- **Windows:** run `certmgr.msc` for the current user. Under **Trusted Root Certification Authorities → Certificates**, choose **All Tasks → Import** and import the public CER file. This is an explicit trust decision. [Microsoft certificate store documentation](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/trusted-root-certification-authorities-certificate-store).
- **Android:** search Settings for **Install certificate** and install the file as a **CA certificate**. On Pixel, see Security and privacy → More security settings → Encryption and credentials; manufacturers may name this differently. [Google certificate instructions](https://support.google.com/pixelphone/answer/2844832?hl=en).

The application does not install trust automatically or bypass browser certificate warnings. If a certificate error remains, check IP, clock, fingerprint and import. Firefox may use its own certificate store. Passwordless access still requires a valid trusted HTTPS connection.

## 4. Open the dashboard

Use the exact HTTPS URL shown by setup, for example **https://192.168.0.95:8766/** only if that is the configured tablet address. Password mode prompts for **citifox** and your network password. Passwordless mode opens directly after certificate trust.

All network clients share the same monitor and target. Language, theme and an inactive preferred target are browser preferences; an active target is shared backend state. API keys, device configuration, generic vehicle commands and backend exit/restart remain local-only in both access modes. The vehicle key never goes to another browser.

## Disable or troubleshoot

Since 1.10.2, opening the static landing page through an external link is allowed when the browser identifies a top-level GET navigation. Previously this could produce `Access from another website is not allowed`, particularly when opening a link on a phone. API reads, session bootstrap, embedded documents and all commands retain the existing origin/session/CSRF and authentication checks. This error is an application policy rejection, distinct from a TLS certificate warning or connection reset.

Run `Setup-Network.cmd --disable` to disable the listener after a clean restart. Remove only the application firewall rule as administrator if no longer required:

```powershell
Remove-NetFirewallRule -Name CitiFoxCharger-Private-LAN
```

On timeout check that the tablet/backend are running, the URL/IP is correct, both devices share a reachable home network, guest-Wi-Fi isolation is absent, Windows uses the Private profile and the firewall rule is installed. Local Settings → Home network access reports listener errors. Password mode throttles five failed sign-ins per client for up to a minute. Passwordless mode intentionally has no password challenge.

Custom profile/ports:

```powershell
Setup-Network.cmd --data-dir "C:\MyDataFolder" --backend-port 8765 --port 8766
Setup-Firewall.cmd --data-dir "C:\MyDataFolder"
```

Use the same profile already used by the backend. Setup windows remain open after success and failure. Certificate creation, strict TLS, both authentication modes and permission boundaries are tested on loopback. A successful physical second-device connection to this wall tablet still requires confirmation.

For the communication diagram and exact device/cloud interfaces, see [COMMUNICATION.md](COMMUNICATION.md). Use **HTTPS**, not plain HTTP, on the network listener port 8766; HTTP sent to that TLS port can be reset before any application response.

## Planned public reverse-proxy access

Public access is not enabled by the current home-network setup. A separate gateway can provide a real domain, publicly trusted HTTPS and mandatory authentication while retaining passwordless private-LAN access. Such a gateway must verify the tablet's upstream TLS certificate and preserve the application's Host/origin/session/CSRF checks; a generic reverse proxy is not automatically compatible with the current IP-only allowlist. Do not disable these checks or forward the tablet's ports directly to the Internet. Public routes should exclude device/key administration, backend process control, updates and experimental vehicle-limit commands. Review the existing gateway before changing ports or services.


## Remote diagnostics and updates

From Settings, authenticated home-network sessions can view/download `GET /api/diagnostics`, start `POST /api/app/update` and follow `GET /api/app/update/status`. This is also enabled in explicitly configured passwordless mode: every reachable home-network device can trigger an update. Update confirmation appears before submitting; existing charging guards, encrypted-key requirement, expected-repository/fast-forward checks, private-host/origin/session/CSRF checks and backend restart verification remain. Standalone backend restart/exit and key/device configuration stay local-only. Diagnostics use cached allowlisted data and never trigger a vehicle request or charging command. The first upgrade to 1.8.11 must still be launched on the tablet because earlier backends reject remote updates.
